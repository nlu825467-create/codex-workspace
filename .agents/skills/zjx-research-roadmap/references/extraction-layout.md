# 研究提取和自动选型

读完整材料再建立路线。每个节点保存短标签、完整说明、阶段、角色、来源。每条关系也保存来源：连线是研究主张，不是空白填充。

不能将“建立模型”擅自改成“随机森林建模”；不能将计划步骤改为已完成；不能把关联研究画成因果验证。只根据用户要求纳入背景、意义等模块，不为套模板而添加泛泛步骤。

关系含义：sequence 为执行顺序；data 为产物传递；supports 为方法/理论支持任务；validates 为验证评价；feedback 为后续信息返回具体步骤；decision 为条件分支。反馈标签说明更新什么，条件标签说明条件。

独立验证必须有明确的不同机构/时间/队列等来源依据。随机测试划分、交叉验证折、同一批样本复测不能单独证明外部验证。不同算法也可能先后依赖，不能仅因名字不同就画成并行。

| 代码 | 主结构 | 要保留的关系 |
|---|---|---|
| vertical | 阶段前后依赖、长主线 | 主轴、阶段标签、局部侧向结果 |
| parallel | 输入分叉、多任务后汇合 | 同层并列、各输入输出、真实汇合 |
| swimlane | 阶段、任务、方法对应 | 阶段行、任务列、方法列 |
| fusion | 多源各自处理后整合 | 各源处理、多输入汇聚、数据身份 |
| validation | 开发与独立验证来源分开 | 分区及独立数据不进入训练 |
| feedback | 后续结果更新前面操作 | 返回箭头、更新对象、明确标签 |

六类不互斥：多源数据联合建模再外部验证，可以用 fusion 主结构加 validation 局部结构；如果开发与验证的对应是主要研究问题，也可用 validation 主结构。真实反馈永远保留，不必全图环形。用户显式布局优先，但不能破坏科学关系。

selection.primary 表达模型判断的核心关系，selection.motifs 记录所有必须保留的局部结构。constraints.independent_validation 和 lane 表达独立性约束，与主结构分别判断。完整画布的几何构图另按 visual-layout.md 决定；不能仅因含外部验证就覆盖真正主导研究的优化闭环或证据链。源头分区、独立性和数据不回流约束照常保留。

程序 auto 建议依据已结构化的信息：独立验证、反馈、三栏 intent、多输入融合、分叉汇合等。它是保守的结构提示，不理解研究贡献，不能直接当成最终选型。复杂路线由模型从主要问题、核心任务及产出判断主结构，显式写入 primary 和 reason，并在 motifs 保留其他真实关系。不要根据标题关键词自动判断。

默认采用黑灰论文配色，白底细框和少量浅灰填充，具体见 academic-color.md。academic/mono/color 三风格；academic 使用灰度层级，mono 使用白底黑字黑线，color 仅在用户或参考要求彩色时采用。角色通过位置、文字和必要形状维持身份，不能只靠颜色。阶段容器表达研究分组，不做 UI 卡片装饰。字号不无限缩小，过密则有依据地概括或分图并核对任务覆盖。

完成检查：关键节点有来源，连接可解释，研究状态正确；无裁切/箭头穿字，分支和反馈可读；从最终 PPT 重新载入渲染 PNG；原生文本和连接端点有效。程序检查不能替代内容和视觉复核，也不能代替用户应用中的实际拖动测试。
