# 右侧浏览器与 Chat 操作

## 工具入口

优先使用环境的 `mcp__cua_repl.js`。遵守当前工具首调用规则，新建页面的入口示例：

```js
let chatTab = await cua.createBrowserTab("iab", "https://chatgpt.com", { visible: true });
```

首次调用只执行该入口，不添加其他 API、等待或截图。读取返回的完整文档后，使用文档实际支持的观察与操作方法，不发明定位、上传、截图或等待 API。

需要展示右侧面板时，可使用宿主 `open_in_codex` 的 browser target、placement right。优先展示实际受控标签；该工具仅展示，不代替读写。避免为显示重复建立对话。

上述工具不可用时，发现当前正式浏览器工具并读其文档。只有 native 控制确实可用、浏览器路径不可行时，才按安装的 computer-use 技能及其必要文档操作。不要自行建立 cookie、隐藏接口、CDP 或登录抓取方案来绕过工具边界。

## 新任务

1. 打开可见 ChatGPT 页面，确认域名及登录状态。需要登录、验证码或 MFA 时请用户完成，不保存凭据。
2. 新建 Chat，确认空白页面，不把任务发送到旧对话。
3. 打开模型菜单，记录实际候选与说明。按“最新”标记或可靠说明确认最新；顺序无法判断时请用户指定，不猜。不将 Auto 当作固定模型确认。
4. 若最新模型不支持要求等级而次新支持，说明冲突，请用户决定，不能静默选次新。
5. 推理设置有极高选极高，无极高有高则选高。其他标签按实际界面解释核验，不能根据名称想当然。均不存在则报告选项。
6. 读取选择后的状态并记录。无法核验时先解决再发送。
7. 填入首轮任务及附件，核对完整性后只发送一次。
8. 确认消息出现并保存对话地址。首轮前尚无稳定地址可先记录 pending。

## 收发完整性

启动前先核对当前任务或用户明确适用范围内已有的模型回退授权。严格最新核验是默认；用户已允许默认模型 + High 时可在该授权范围继续，记录型号未知和实际强度，不重复求同一确认。不可从其他任务的一次选择推导新任务授权。按 SKILL.md 的官方核查流程处理菜单无最新标记情况。

大规模代码交付前确认一个小文件可通过工具允许的常规方式读取并保存。附件拒绝与正文读取权限分别按实际工具规则判断；明确禁止替代传递时不得请求变体绕过。只允许附件路径受限而常规正文读取允许时，可以请求标准代码正文，保留来源及完整性记录。允许范围不明时按拒绝执行，不假设换通道获准。

- 每次核对这是本任务对话，再发送用户消息。
- 发送延迟时先检查已送达消息，不能立即再点发送。
- 依据页面生成状态及最终 assistant 消息判断结束，不用固定等待冒充完成检测。
- 分段等待，每段不超过约 60 秒；Chat 搜索或调用工具时不把中间状态当最终答案。
- 读取完整最后回复，保留代码块和参数，不只读第一屏。
- 截断时请求从准确位置续写，补齐当前批次。
- 按工具真实支持能力上传附件，不支持则发送必要原文和证据，不假称上传成功。
- 恢复时用原 URL 获取标签或打开原对话，核对尾部消息后继续。
- 对话不可访问时记录原因；确需迁移时验证新配置并传入恢复包。
- 登录失效、额度不足、模型或等级不可用时保存断点并报告，不静默降级。不修改账户级设置、订阅或无关聊天。
