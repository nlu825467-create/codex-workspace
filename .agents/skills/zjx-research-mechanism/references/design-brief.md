# 绘图前的专属设计说明与工具提示词

在科学底稿完成后、首次图像生成之前，自动写出本图 `design-brief.md` 和 `reference-prompt.txt`。它们是内部绘图依据，默认无需用户确认，也不在最终回复中全文展示。“科研投稿级别”须落实为以下具体决策；记录本图实际选择，避免把检查清单当成设计成果。

## 专属设计说明的六项内容

| 内容 | 本图必须落实的决策 |
| --- | --- |
| 科学表达 | 一句话核心结论；实际实体和区室；关键条件；主链和确有支持的支路；每条关系的作用类型、证据状态及符号。区分直接结合、功能激活、磷酸化、运输、转录和表型，不因画面流畅补造步骤。 |
| 构图层级 | 选择适合本图的画布比例、主阅读方向、主体相对位置、视觉中心和留白；说明主链如何穿过正确区室，支路如何避让；哪些对象突出，哪些背景降低权重；避免关键对象意外裁切。 |
| 生物插画质感 | 对应物种与细胞类型的形态；主要对象的轮廓、尺寸层级、统一光照和柔和阴影；背景纹理密度。按研究需要选择细节，结构性背景不能被误读为新增机制节点。 |
| 色彩与文字 | 主辅色 HEX、每种颜色对应的实体类别、箭头和文字色；颜色与位置共同传递信息，保持灰度下的关系可辨性；字号层级、常见字体、标签落点、图例和留白。科学限定词、上下标与符号保持准确。 |
| 投稿与交付条件 | 图的用途（机制示意、工作模型或 graphical abstract）、语言、宽高比、物理尺寸、背景和输出格式；用户指定期刊时核对其当前官方图件要求并记录来源与核对日期，覆盖涉及的尺寸、字体、分辨率和格式要求。未指定期刊采用通用专业设计目标，不声称满足特定期刊规范。 |
| 视觉验收 | 根据上述选择写出可观察的检查点：科学链路可追踪、主体突出、空间关系准确、形体自然、光照一致、色彩协调、标签清晰、无遮挡裁切、背景不干扰主链。按最终物理尺寸检查可读性；不使用无依据的美观分数或相似度百分比。 |

物理尺寸、字体与分辨率是成图/导出要求。根据生成画布像素换算标签占比，在 SVG 中落实字体与最终尺寸；不能仅凭图像工具提示词中的“600 dpi”就认为输出满足分辨率要求。当前 180 mm、600 dpi TIFF 是默认交付设置，用户要求或已核实期刊要求优先。

设计说明可以简短，但每项必须包含本图的实际决定；不强制每种研究都出现细胞、受体或核转位。只选用与其科学内容匹配的结构。科学条件冲突按底稿流程处理，日常视觉选择由 agent 自行完成。

## 从说明组装实际工具提示词

`reference-prompt.txt` 必须是一份自包含的完整绘图提示词，内容实际传入图像生成工具。组织顺序建议为：

1. **绘图任务与核心叙事**：用一到两句话说明本次研究所需的图和核心结论；模拟研究明确标记，实际研究不添加模拟标签。
2. **实体与科学连线**：逐项写出实际对象、区室、作用方向和符号；需要虚线的具体边、关联线和条件明确到对象，避免“实虚线按需使用”等模糊表达。
3. **本图布局**：画布比例、主体相对位置、主阅读路径、对象层级、标签留白、图例位置与边缘空间；根据实际链路选定布局，不套用旧示例坐标。
4. **具体视觉要求**：从设计说明展开本图形态、光源、光影、主辅色及其用途、背景细节密度和文字层级。采用 `art-direction.md` 中适用的精细生物插画规则，并针对本图列出需要避免的视觉问题。
5. **准确标签**：展开本图完整 `label_manifest` 中需显示的文字，保留大小写、上下标、限定条件和图例；清楚关联标签与对象，不把示例名称带入实际研究。
6. **质量目标与边界**：明确完整画面、正确关系、最终尺寸可读性、无标签遮挡及无意外裁切；仅绘制规定的科学实体与关系。具体期刊要求只写已核实且图像工具可以落实的设计条件，其他条件由后续 SVG/导出阶段完成。

文件名或路径不会替代提示词内容。不要只发送“按专属设计说明绘图”“顶刊级”“高级美观”等描述。第一次生成保存 `reference-prompt.txt`，每次修正保存实际提示词，例如 `reference-prompt-revision-1.txt`；局部修正说明需要改变的位置与效果，并保留正确的机制关系。

## 生成后的两类检查

科学检查逐条对照底稿。错误因果、错误区室、关键节点缺失、未经支持的新增机制属于必须修正的问题；不能因视觉漂亮忽略。文字伪影按主流程修正并记录，底稿始终是标签依据。

视觉检查对照本图设计说明，查看实际参考图并考虑最终尺寸：主链能否迅速追踪，主角与背景是否有层级，细胞和分子是否自然，光影是否协调，标签是否清晰，箭头是否避让，边缘和纤维等细节是否有留白。记录具体位置和现象，例如“核转位标签与核膜重叠”或“背景纹理与主蛋白同样显眼”，再写对应的修正要求。

在 `run-review.json` 中分别记录科学检查、参考图视觉检查、SVG 还原检查和导出检查的观察、修正及未解决项。格式检查只能证明相应技术条件；参考图美观也不能证明科学关系正确。遵守主流程的修正次数上限，不为追求主观完美无限重绘。

SVG 重建沿用同一设计说明，并对照实际参考图检查轮廓、位置、光影和文字。为了科学纠错或用户的新视觉要求需要修改设计时，同步更新说明并记录原因；不能在矢量化阶段悄然替换布局或把精细插画降为规则几何图标。
