# 成稿质量控制

目标：交付用户能直接审阅、编辑并按已知要求使用的完整开题报告。章节齐全、文件生成、模型自评或用户同意，均不能单独证明达到成稿要求。不承诺学校必然批准；未获知学校规定时只能说明采用建议格式。

## 一、写作前确定本次验收依据

从用户要求、主学科/专业、研究路径和适用模板提取：必含内容、内容深度、方法所需细节、引用及格式。每项记录来源、正文落点、检查方式及结果。没有正式篇幅时先提出适合任务的内容安排；不能靠固定字数代表质量。

博士内容另按 [博士验收](doctoral-quality.md) 检查学术定位、原创潜力、关键解释/论证与整体论文路径。格式与方法操作合格不代表博士内容通过；开题审查原创潜力及可行性，不要求预先得到全部原创结果。

重要研究问题和路径尚待用户决定时继续独立工作，等待决定或整体授权，不越过交互。已给定/授权的事项直接落实，不能为了增加关卡反复求确认。

## 二、从阶段成果到可成文方案

正文前应有具体问题、证据定位及可执行设计；下列缺口必须解决，不能包装成漂亮文字：

- 只有主题，没有对象、范围与可回答的问题。
- 立题依赖的关键判断没有核验来源，或来源不支持它。
- 设计只有方法名、软件名和流程箭头，不能说明如何取得证据。
- 方法不支持拟声称的结论，或关键资源明确不可得且无替代路线。
- 贡献、样本/实验规模和进度相互矛盾。

补检索、细化设计或调整范围后再成文；会改变用户方向的修订需对齐。未来按计划取得的许可/数据可作为实施安排，不要求研究已完成，但须有合理取得路径和失败应对。

## 三、逐部分内容验收

以下为论证任务，不要求每项独立成章；按学科和模板映射。

| 内容 | 必须能回答什么 | 常见不通过表现 |
|---|---|---|
| 立题与价值 | 哪个具体问题，为什么在当前知识/情境下值得研究 | 大量宏观口号，实际问题无依据 |
| 研究现状 | 已知什么、如何得知、有何分歧，如何引出本题 | 逐篇罗列，遗漏直接相关工作，以“少有人研究”充当全部价值 |
| 问题与目标 | 研究边界和拟得到的认识/产出是什么 | 目标无限扩展，目标只是重复方法名 |
| 研究内容 | 每个任务回答哪个问题，任务如何衔接 | 多项任务互不相关，核心问题无人回答 |
| 设计与方法 | 用什么材料、怎样取得/处理/分析、怎样形成判断 | 仅列软件/方法，不交代选择理由和关键细节 |
| 可行性与限制 | 时间条件如何满足，核心风险失败后怎么办 | 无事实依据地称条件成熟，替代方法不能回答原问题 |
| 贡献与成果 | 相对已有认识增加什么，设计能否支持 | 空泛首次/突破，保证阳性结果或发表 |
| 进度 | 工作依赖、时间和资源是否匹配 | 无收集/分析/返修时间，生长季等约束被忽略 |

必要细节由学科标准决定。例如实验设计需独立单位与对照，文史需材料范围和分析/考证步骤，规范论证需前提、依据与反论，实践研究需过程记录和评价。不能用一套实验清单验收所有报告。

## 四、证据和一致性两次回查

**证据回查**：逐项核查立题、主要研究现状、方法依据、关键数字和规范判断，记录来源位置与可支持范围。核对书目身份、正文支持、引述精度以及正文—文献双向对应。来源存在不代表已支持论断，不能只检URL能否打开。无法核实则换来源、改为有依据的较弱判断或删除；关键立题仍失去支撑时返回上游。

**全文一致性回查**：逐个问题追到目标、内容、取证/论证、分析、可能结论和贡献；检查对象、时间、样本/材料、术语、方法、进度及用户决定是否前后一致。修改某一处数字或方法后更新相关内容，不能只改一段。已有成果、拟议研究和假设严格区分。

不要求背景常识每句都附引用，但重要可争论的事实与判断必须有适当支持。对规范/时效资料使用当前适用来源，其他学校写作指南不作为课题知识证据。

## 五、成文与文件检查

报告正文是完成的学术文本，不夹杂“这一节可以写”“建议补充文献”“后续请自行展开”等写作指导。行政信息可保留必要填写位，研究主体不得以占位符、空表或泛化套话交付。

立题、目标和贡献先明确课题要增加的认识与用途，再在适当位置集中说明适用边界。不能用反复的“不保证、不声称”替代正面论证；保留必要限制，删除不增加信息的重复声明。

检查是否以研究者身份陈述计划。把“不得编造、这一节应怎样写、不能仅写后续解决”等制作与验收指令留在内部记录，正文改为真实准备状态、获取路径和研究步骤；测试隔离、适用范围及尚未落实的现实条件属于研究本身，不能作为“过程用语”一并删除。

将文献获取、元数据纠错和质量关卡的操作说明留在记录；正文保留准确的学术定位、必要的版本注释及实质论证。不能只删除“不算创新”等句子使文本显得成熟，而应把它所暴露的立题缺口补成有依据的比较和正面主张。

默认生成可编辑Word（.docx），有明确其他格式要求则服从；无模板时按 [文书适配与建议配置](word-format.md) 执行，可保留完整文本备份。核查实际文件与定稿文本相同，没有漏章、乱码、公式/特殊字符损坏或引用丢失。使用可用文档技能/工具完成排版与渲染；Word需要实际逐页检查，不能把打开压缩包/XML当作视觉验收。正式模板或本次有依据的建议配置逐项核对文书形态、必填栏目/附件、字体层级、编号、行距、表格、页码等适用项；不将自行选择的样式写成官方规定。

文件工具或渲染能力确实不可用时先尝试可用替代，再如实交付完整内容并注明具体格式检查缺口，不虚称DOCX/视觉验收完成。不要用泛化“仅供参考”掩盖实际问题。

## 六、集中审阅、修订与交付判定

完成初稿后单独做一轮集中审阅，先冻结当前文本，以验收依据寻找反例和缺陷；记录具体位置、依据、影响及修改。该自审不称独立审稿，也不默认启动其他代理。修订后复查受影响内容，只有新变化或问题未解决才扩大检查，避免空转。

博士初稿从学科定位、方法证据和整体论文可行性分别找最可能动摇方案的问题；优先查主张是否已被已有研究回答、概念是否参与设计、证据如何支撑贡献及各部分整合逻辑。正文变长、伦理周密、引用编号对应或用户认可，都不能抵消这些缺陷。按博士专项返回修订，避免只润色。

博士通过结论须指向当前核心论证及其证据/设计与正文落点，并说明针对最有力质疑的处理；核心问题仍未知时保留缺陷，不只给总评或自评分。形式检查、有限桌面走查、单次自审与真正博士题目的端到端内容审查分别记录，不能互相替代。对修订后弱化的主张，重查博士研究价值，而非因不再过度声称就自动放行。

集中审阅将最关键的结论逐项反写为所需证据，专查全文中的“只有、无损害、机制、长期、通用”等超出当前比较/时间/材料的用语。自审不仅查是否写过限制，还查限制后是否剩下值得研究且能够形成判断的核心任务；关键精度、对照或理论对象仍未落定时，不能因已写“未来预试”而关闭缺陷。未来参数可待预试，但当前需交代合理范围、更新规则、资源上限及失败后的真实选择，不要求在开题前完成全部实证。

内容判断回答“主张成立与否、证据如何产生及关键选择是否可执行”，不能只复述已遵守哪些程序。每个影响成稿的缺陷定位正文，并区分确定错误、实施歧义、主张超范围及可选增强；不能把合理的受限设计说成一律无效。后续审阅推翻先前通过判断时，记录新的有效状态及理由，保留已完成的文件/页面检查范围；科学状态与文件状态不得互相抵消。修订规则不等于旧报告已返修通过。

缺陷关闭以修改后的实质内容为据，直接记入已有记录，不新增一套通用评分：

| 缺陷 | 关闭依据 | 不能代替关闭的动作 |
|---|---|---|
| 原创定位不足 | 最接近工作比较支持一个具体且重要的剩余问题与拟推进 | 增写创新点、承认尚需论证 |
| 核心概念不清 | 解释概念选择的理由及其对材料、设计或推理的实际影响 | 罗列定义与理论名称 |
| 方法不能支持主张 | 改变依据或设计；收缩主张时重新论证研究价值 | 只补局限或未来预试 |
| 整体贡献不足 | 核心部分各承担必要任务，共同支撑可辩护的贡献 | 增加章节、案例或周期 |

发现影响成稿的缺陷后，返回对应阶段继续修复并复核受影响部分。用户要求审阅或试跑时可按任务交付冻结稿与审阅结论；完整撰写任务不能默认以“草稿加重大缺陷清单”收尾。关键文献与理论准备缺口优先在当前任务补足；确需改变用户方向时，给出已有依据、路线及取舍供其决定，不把选题设计转交用户。

将缺陷分为：
- **影响成稿的缺陷**：关键证据、设计、用户决定、实质内容或要求的文件/格式未落实。解决前不能标“可直接使用成稿”。
- **表达或呈现问题**：冗余、段落不清、编号或布局等。能修的先修，不能以不影响科学性为由留下明显影响使用的问题。
- **未来实施事项**：方案中已有合理安排但研究尚未开展，如计划申请许可、进行预试。这是开题本身允许的未来工作，不自动构成成稿失败；若根本不可行则归入第一类。

最终状态：
1. **成稿（按已知要求）**：内容、证据、设计、用户决定和要求的文件检查均完成，无影响成稿的未解决缺陷。没有学校格式时明确“采用学科建议格式”，不称完全符合本校提交规范。
2. **完整草稿/核查未完成**：仍有关键证据、设计或文件检查限制。交付已完成内容、指出具体影响，并继续修复；不能把该状态当作已达成完整任务。
3. **阶段成果/待关键决定**：待用户选择且无法授权推定。保留任务和已做工作，不把提纲当成报告。

默认对用户交成品与简短说明，内部核查表不混进报告正文。用户反馈后继续修改；只有落实反馈并复核才能将该版视为最终交付。

## 七、程序检查与试跑的证据范围

程序结果只覆盖实际读取并比较的对象。核查正文中的实验数量、预算和跨章节一致性时，应从实际文稿提取相关设置，或由审阅者把当前文稿对应位置核对到结构化计划；单独在程序内重算预设常量只是计划算术，不能证明正文一致。无法可靠提取时人工核查并标明，不能用脆弱的通用正则伪装科学验证。

引用编号对应不等于来源支持论断，标题齐全不等于论证完整；结构检查与内容、证据、方法检查分别报告。正文修改后，对受影响的检查重做，旧文件校验结果不能沿用给新稿。

程序核查不得用预设书目白名单证明引文完整；按 [证据指导](evidence.md) 从实际正文双向查。报告中的核心数值规划若依赖已执行模拟，应能提供相应输入、生成/分析假设、种子、实现及输出，作为必要的可复算说明或附件，不把内部记录全部倾倒给用户。仅保存输出数字、做近似复算或检查算术，不称精确复现模拟。

复审另核对“实现可复现”和“实现回答本题”是否分别成立；后者对照主要目标、真值、分配、缺失与实际结论。主要比较、对象或指标改动后，同步检查立题、问题、样本、分析、贡献及附件，不能只替换方法段的名称。针对性复审使用当前冻结版本，记录缺陷实际关闭依据；最多轮数或已投入工作量不能成为降低标准的理由。

数值验证遇到不可估计、模型失败或缺少可用单位时，预定其报告和后续处理，不悄悄删除失败重复后用剩余结果声称全部可靠。覆盖率与区间宽度、偏差及适用情景一同判断，过宽区间的高覆盖不等于足以回答问题。

评估或迭代skill时，除了顺利完成案例，按风险选择能实际触发返回的情境，例如文献已回答问题、资源不支持主方案、用户拒绝推荐或中途改题。执行“识别问题—返回对应阶段—修订—同步受影响内容—复核”，记录做了什么和未通过项。可以是局部桌面演练，无需每次重跑全文；预设刺激、自拟答复和模型自审均不称真人验证或独立行为验证。一次演练只支持对应范围，不证明其他学科表现。
